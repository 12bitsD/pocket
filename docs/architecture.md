# Pocket 总体架构

状态：**已定稿，2026-11-23。**

Pocket 面向个人自托管优先场景，按真实使用场景拆分为**两个完全独立的客户端应用**（**时间与日程 `calendar`**、**笔记 `notes`**），共用一套轻量私有云端 **`cloud/`** 与外部 Agent HTTP 接入契约。详细云端协议见 [Cloud 架构](cloud/architecture.md)，时间与日程领域规则见 [Calendar 领域架构](cloud/calendar.md)，界面规范见 [Pocket 设计标准](design-standard.md)。

## 1. 产品形态与边界

```text
                        ┌──────────────────────────┐
                        │       External Agent     │
                        │  Prompt / Run / Session  │
                        └──────▲────────────┬──────┘
          HTTP Prompt Delivery │            │ 受限密钥按授权读取日程/笔记
                               │            ▼
┌──────────────────────────────┴────────────┴──────────────────────────┐
│                  Pocket Cloud (cloud/ · Docker 自托管)                │
│     Identity / 6位配对码 / Link 同步 / Scheduler / Prompt Delivery    │
└───────────────────▲──────────────────────────────▲───────────────────┘
                    │                              │
        ┌───────────┴───────────┐      ┌───────────┴───────────┐
        │    Pocket Calendar    │      │     Pocket Notes      │
        │ 今日日程 / 月历 / Todo │      │   独立笔记应用（规划中）│
        │ 独立安装包 & 独立网页端 │      │  独立安装包 & 独立网页端│
        └───────────────────────┘      └───────────────────────┘
```

- **按场景彻底拆成两个独立软件（不做臃肿全家桶）**：
  1. **Pocket Calendar（时间与日程，当前主线）**：把日常日程、月历、个人闹钟和 Agent 定时任务收进干净的三栏（`今日日程 / 月历 / Todo`），使用同一套 `@me`（手机响铃）与 `@agent`（云端投递 Prompt）指派交互。
  2. **Pocket Notes（笔记，下一阶段专项打磨）**：完全独立的第二个应用，安装包与界面入口均与时间管理分离，专注写作沉淀与按篇授权给 Agent 读取。
- **一套私有云端共用**：两个独立客户端连接同一个个人部署的 `pocket-cloud` 服务，无需维护两套服务器与数据库。
- **客户端发布与实现**：客户端安装包统一通过 **GitHub Releases** 分发；一套模块化前端界面同时输出网页端与 Android 安装包（Capacitor 7 + Kotlin 薄原生插件：设备加密区原生 SQLite、未解锁开机恢复、`setAlarmClock` 精确响铃、全屏锁屏唤醒与权限一键自检卡）。

## 2. 免注册登录与设备配对

- **首台设备登录**：`pocket-cloud` 首次启动加载初始主密钥，用于电脑端首次登录。
- **6 位短时配对码绑手机**：在已登录端生成 5 分钟有效的 6 位配对码，手机 App 输入后换取该手机专属的长期设备凭证并建立实时同步连接；设备可单独吊销。

## 3. 两条核心触发链路

1. **`@me` 个人响铃（设备执行）**：在本地或网页端设置 `@me` 闹钟／日程强提醒 → 同步至目标手机原生安全库并注册系统闹钟 → 手机设置成功后回传真实 `EXECUTED`（网页端本身不响铃）。
2. **`@agent` 定时任务（云端投递）**：到点由 `pocket-cloud` 生成唯一 `delivery_id` 与一次性回调密钥，HTTP POST 到绑定的外部 Agent 地址 → 收到 `202 Accepted` 标记 `COMPLETED`（不依赖手机在线，可选回传执行摘要挂回原 Todo 下方）。

## 4. 分步落地路线（详见 [整体开发方案](development-plan.md)）

1. **Step 1（后台底座 + 首批 CLI）**：落地初始密钥登录、6 位手机配对码、Agent 权限密钥、外部 Agent 地址加密保存与配套 CLI 命令。
2. **Step 2（日程/Todo + 定时唤醒 AI + 触发 CLI）**：完成日程冲突检测、统一 Todo（含本机锁）、后台定时投递重试、摘要回写与 `trigger` 调试命令。
3. **Step 3（多端实时同步 + 同步 CLI）**：打通变更日志、长连接断线补齐、手机响铃回执推进、`sync watch/ack` 调试命令与 CI 自动测试。
4. **Step 4（网页端正式接入）**：前端模块化改造并连上真实 `pocket-cloud` 服务完成日常可用闭环。
5. **Step 5（安卓真机包 + GitHub Release）**：封装 Capacitor + Kotlin 原生响铃插件（开机未解锁恢复、全屏响铃页、权限自检卡），发布 `calendar-v*` 安装包至 GitHub Releases。
6. **后续阶段（独立 Notes）**：单独设计与开发第二个独立应用 `Pocket Notes`。
